# Pokemon Bank 上传补丁设计

## 范围

上传补丁用于把离线修改后的本地文件重新提交到服务端，不复用过期会话的控制数据。

## 联网重新上传顺序

1. 正常完成联网认证，并把服务端最新文件下载为 `remote`。
2. 取得当前会话新生成的 32 字节事务描述；不得从 `bankdata.bin` 或旧会话复制。
3. 以槽为粒度比较上次同步的 `base`、离线修改的 `local` 和新下载的 `remote`。
4. 将无冲突的本地槽修改合并到 `remote`；身份、计数、时间戳及其他控制相关字段保留最新远端值，除非其更新语义已经确认。
5. 同一槽在本地和远端发生不同修改时停止上传，并保留三份输入。
6. 将合并后的完整对象交给原程序的序列化、远端暂存、卡带保存和提交/回滚流程。
7. 仅在原服务器提交明确成功后，更新 `base` 和本地工作文件。

## 安全限制

- 服务端对身份字段、修订号、计数和逐槽时间戳的校验规则尚未确认。
- 第一次验证仅使用相同账户、已有备份的文件和一个非关键槽修改。
- 暂存、卡带保存或提交任一步失败时，都不得推进本地同步基线。
