# 第二步：离线补丁

## 用途与文件

本补丁把 Pokemon Bank 的远端银行数据操作重定向到一个本地文件，同时保留原版
游戏选择、银行盒子和游戏保存逻辑。

| 文件 | 用途 |
|---|---|
| `sd:/3ds/Bank/bankdata.bin` | 当前完整银行文件（`0xBB518` 字节） |
| `sd:/3ds/Bank/bankdata.tmp` | 保存时完整写入的候选文件 |
| `sd:/3ds/Bank/bankdata.bak` | 提交时保留的上一份完整文件 |
| `sd:/3ds/Bank/bankdata.bin.break` | 无法识别的主文件逐字节保全副本 |
| `sd:/3ds/Bank/bankdata.bak.break` | 无法识别的备份文件逐字节保全副本 |

需要创建本地文件时，补丁会自动创建 `sd:/3ds` 和 `sd:/3ds/Bank`。如果已经存在的
`bankdata.bin` 无效或缺失，补丁会优先从正常可读且有效的 `bankdata.bak` 恢复；
如果两者都无法用于恢复，则先把实际存在的每一个无效文件复制到对应的 `.break`
路径，再进入原版首次创建。缺失的文件不会生成虚假的 `.break` 占位文件。

## 总体路线

```text
标题界面／账户检查
        │
        ▼
“正在连接中……” ── 在本地强制判定网络可用
        │              不创建远端连接作业
        ▼
检查 bankdata.bin 的文件长度与格式头
        ├── 有效 ──────────────► 既有记录模式 4
        └── 缺失／无效
                  │
                  ▼
             检查 bankdata.bak
                  ├── 有效 ────► 完整读取 0xBB518 字节
                  │                复制为 bankdata.bin；保留 .bak
                  │                不生成 .break
                  │                └────────► 既有记录模式 4
                  └── 缺失／无效
                            │
                            ▼
                  将每个实际存在的无效文件复制为 .break
                            ├── 初次复制失败 ─► 每个文件最多再重试 3 次
                            └── 成功／共 4 次均失败／两者均缺失
                                           └──► 首次使用模式 5
                                      │
                                      ▼
按主机当前时间刷新“当前时间 + 999 天”的运行时离线票据
                │
                ▼
交给原版首次使用判断
        ├── 模式 4 ─────────────► 功能选单
        └── 模式 5 ─► 原版首次使用提示
                         │
                         ▼
                    跳过远端记录 ID 子状态 4-5
                         │
                         ▼
                    原版空对象初始化
                    （本地化盒名和创建日期）
                         │
                         ▼
                    直接写入 bankdata.bin
                                              │
                                              ▼
                                           功能选单
```

普通启动检查只读取文件偏移 `0x15C` 的 4 字节格式头；恢复时会额外完整读取并验证
备份，之后才进行复制。主文件有效或能从有效备份恢复时绝不生成 `.break`。没有
有效恢复来源时，只尝试复制实际存在的无效文件。每个文件初次复制失败后最多再重试
三次；共四次均失败会保留原始无效文件，但不再阻止首次创建。
如果两份文件都不存在，则直接进入首次创建。原版 state 9 的首次使用判断继续保留。
因此，不存在有效主文件或备份时仍由软件自己的首次使用流程
取得主机／账户数据并显示原版提示。远端记录 ID 获取子状态会被跳过，但原版空对象
初始化仍会初始化 100 个本地化银行盒子并填写真实创建日期。最后的远端创建替换为
带完整检查的 `bankdata.bin` 直接写入。首次写入失败时会删除残缺文件；普通保存
流程才继续使用 `.tmp` 并维护 `.bak`。

票据到期时间只写入运行时状态。`bankdata.bin` 中已有的身份字段和创建日期不会被
票据补丁重写。

## 读取与使用银行

```text
功能选单：使用 Pokemon Bank
        │
        ▼
原版游戏选择与游戏软件检查
        │
        ▼
“正在连接本地离线银行数据……”（至少 2 秒）
        │
        ▼
关闭原版旋转等待界面及其循环音效
        │
        ▼
从 bankdata.bin 精确读取 0xBB518 字节
        ├── 读取／格式失败 ─────► 报错
        └── 有效 ───────────────► 重建流程元数据
                                      │
                                      ▼
                              恢复原版本地子状态 6–10
                                      │
                                      ▼
                              跳过奖励服务器状态
                                      │
                                      ▼
                                原版银行盒子界面
```

只有选定游戏后才会载入完整本地文件。补丁跳过共用银行数据同步状态中的远端请求
部分，然后恢复它原有的元数据复制和所选游戏回调。盒子浏览、Pokemon 移动、检查
及与游戏的交互仍使用原版代码。

原 Pokemon HOME 菜单项改名为“选择语言”，并转入原版语言选择流程，不会进入
HOME 银行数据路径。更改语言后，返回标题的变体会选择新增的空白文本，避免用新
语言字库绘制上一种语言的提示。返回标题前，补丁会把待提交的语言与日文汉字模式
写入原版持久化设置对象，启动原生保存模式 0 并等待完成。因此无需再点击一次标题
界面，直接重新启动也会保留新语言。

## 保存、提交与回滚

```text
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ───────────────► 保存失败；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
              │
              ▼
原版卡带／数字版游戏保存
        ├── 失败 ─► 删除 bankdata.tmp ─► 保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
                                      ├── 成功 ─► 断开连接
                                      └── 失败 ─► 尽可能恢复 bak
```

本地暂存写入是同步操作，但完成后会进入一个非阻塞的两秒状态机延时。画面仍会刷新，
也不会重复写入文件。只有原版游戏保存结果成功后才会提交新银行文件。删除、改名、
关闭、文件长度、实际写入量、恢复和回滚结果都会检查。

选择不保存并结束时，不会安装新的 `bankdata.bin`。

## 显示与断开行为

LayeredFS 资源覆盖全部十种受支持语言：

- 初始互联网提示改成通用的“正在连接中……”。
- 选定游戏后的服务提示会明确表示正在连接本地离线银行数据。
- 本地连接延时结束时，补丁会显式关闭原版旋转等待界面，避免其循环音效延续到
  银行盒子界面。
- 保存提示会表示数据正在写入本地离线文件，而不是发送到服务器。
- 普通 state 20 退出显示“正在断开连接……”，本地首阶段等待 1.5 秒完成，不创建
  远端断开作业。
- 更改语言使用的 state 21 会使用前述空白文本，并在返回标题前完成原生本地设置保存。

上实机前请先在模拟器中使用备份测试。
