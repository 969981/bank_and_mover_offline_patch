# 原版与离线合并补丁

这是 Poke Mover v5.5.0 本体 `00040000000C9C00` 当前维护的补丁。它把已经验证的
独立离线功能与精确返回原版程序的运行时路线合并在一起。

Poke Mover 没有下载模式。它既不会创建新的本地银行，也不会下载本工程所用的本地
文件。请先使用 Pokemon Bank 合并补丁的下载模式取得
`sd:/3ds/Bank/bankdata.bin`，或通过 Bank 离线模式的首次初始化生成该文件，再使用
Poke Mover 的离线模式。已经废弃的 Mover 独立下载实验不属于正式流程。

上传补丁也已经永久废止。离线传送只提交到本地银行文件，本工程不会把它上传至官方
服务。

## 模式选择

标题界面默认显示**离线模式**。按实体 **R** 键可在**离线模式**和**原版模式**之间
切换。模式文字位于 HOME 选单说明下方，使用与 Bank 补丁相同的按键字形，并会立即
刷新。

按 **A**、**START** 或触摸下屏时，当前显示模式会锁定为本次会话模式。离开标题
界面后 R 键不再切换模式。

```text
标题界面（默认：离线模式）
        │
        ├── 按 R ──────────────► 原版模式
        ├── 再按 R ────────────► 离线模式
        └── A / START / 触摸
                  │ 锁定当前显示模式
                  ├── 离线 ─► 本地 bankdata.bin 与本地事务
                  └── 原版 ─► 官方联网与服务器流程
```

## 两种模式严格隔离

旧离线补丁涉及的每个钩子都会先读取已经锁定的会话标志。离线模式进入本地实现；
原版模式则精确重放被覆盖指令，或恢复原函数后续路线，包括：

- 网络可用性与连接作业；
- 票据处理；
- 第五世代及第一／二世代合法性请求；
- 服务器银行数据下载；
- 传送资格与候选构造状态；
- 远端暂存、提交、回滚和断开连接。

因此，原版模式不会读取、写入、创建、改名或删除 `sd:/3ds/Bank/` 下的任何文件，
并完整保留原版服务器流程与原版文本。

原版消息条目保持不变。LayeredFS 档案只追加两条标题模式文本和四条离线连接／保存
文本；运行时钩子仅在离线模式选择这些新增条目。软件自带的十套语言资源都会重建并
验证。

## 离线模式使用条件与本地文件

离线模式使用与 Pokemon Bank 相同的文件：

```text
sd:/3ds/Bank/bankdata.bin
```

该文件必须已经是长度恰好为 `0xBB518` 字节的有效当前格式银行对象。Poke Mover
不会执行 Bank 的缺失文件恢复或首次使用创建；文件缺失、不可读、长度错误或格式无效
都会进入错误路线。

开始新一次传送前，本地传送盒必须为空。补丁绝不会覆盖已有的传送盒内容。上实机测试
前请备份 `bankdata.bin`。

## 离线传送路线

```text
原版来源游戏选择
        │
        ▼
通用“正在连接中”提示
        │
        ├── 在本地报告网络可用
        └── 不创建远端连接作业
        │
        ▼
按主机当前时间设置“当前时间 + 999 天”的运行时离线票据
        │
        ▼
连接本地离线银行数据（至少 2 秒）
        │
        ▼
原版卡带读取、筛选与 Pokemon 转换
        │
        ├── 第五世代合法性请求 ─────► 已验证的本地后续位置
        └── 第一／二世代合法性请求 ─► 已验证的本地后续位置
                                              │
                                              ▼
                                  在本地完成远端检查状态
                                              │
                                              ▼
                           载入并验证完整 bankdata.bin
                                ├── 无效／缺失 ─► 报错
                                ├── 传送盒非空 ─► 原版消息 5；保留文件
                                └── 传送盒为空 ─► 原版确认界面
```

原版候选转换状态继续负责读取来源游戏、筛选记录并构造传送候选；离线模式只绕过其中
两处服务器合法性请求。

载入 `bankdata.bin` 前，补丁会先用原版传送槽对象保留候选。完整验证本地银行后，
只有传送盒为空才会恢复候选。原版槽写入操作会同时更新每个 `0xE8` 字节记录及其
并行标签；补丁不会用原始槽字节覆盖已有内容。既有账户身份字段保持不变。

## 离线保存事务

```text
用户确认传送
        │
        ▼
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ─► 中止；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
        │
        ▼
原版来源游戏保存
        ├── 失败 ─► 删除 tmp；保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
        ├── 成功 ─► 原版断开路线
        └── 失败 ─► 尽可能恢复 bak
```

本地暂存、提交和回滚只替换对应的远端事务。暂存写入是同步操作，之后进入非阻塞的
两秒状态机延时；画面继续刷新，文件不会写入两次。只有原版来源游戏保存成功后才会
提交。文件关闭、长度、实际写入量、删除、改名、恢复和回滚结果都会检查。

没有可传送 Pokemon 或用户取消时，原版“不传送”路线保持不变；其最后一次远端事务
会在本地完成，再进入原版断开流程。

## 离线显示与计时

- 初始联网文字改成通用的“正在连接中……”。
- 本地银行数据连接提示至少显示两秒，之后才继续原版卡带读取与转换。
- 保存提示会明确表示正在写入本地离线银行数据；完整暂存写入后至少继续显示两秒。
- 断开提示使用通用文本；已有的本地首阶段仍为 1.5 秒，并且不创建远端断开作业。

等待界面、旋转动画和节奏音效仍只由原版状态函数管理。离线更新通过原状态对象报告
工作完成，之后由原版状态退出路径统一清理。

## 源码布局

| 文件 | 作用 |
|---|---|
| `main.s` | 标题模式锁定，以及每个离线钩子的模式分派 |
| `patch_messages.py` | 为十套语言档案追加并验证标题／离线文本 |
| `message_archive.py` | 自包含的 GARC 与加密消息文件编解码器 |
| `verify_patch.py` | 验证基底哈希、代码区域、钩子、原版重放、IPS 还原与资源 |
| `Makefile` | 编译共用离线实现、注入代码、创建 IPS、重建文本并写出发行目录 |

## 编译与安装

设置 `DEVKITARM`，并把用户自行提取的输入放到
`mover/rom/exefs/00040000000C9C00.dec.code` 与 `mover/rom/romfs/`。工程只跟踪
`mover/rom/.gitkeep`；代码镜像与 RomFS 均被 Git 忽略，必须从用户自己的软件中提取。
仍可显式覆盖 `ROMFS_SOURCE`。文本重建需要 Python 3。

```sh
make -C mover/src/3-combine_patch all
```

完整发行包生成于：

```text
mover/release/3-combine_patch/luma/titles/00040000000C9C00/
├── code.ips
└── romfs/
```

将生成的 `luma` 目录复制到 SD 卡，并启用 Luma 游戏补丁。校验器会检查受支持的
基底代码哈希、可执行区边界、每个钩子与原版模式续接位置、IPS 逐字节还原结果，以及
全部原版本地化文本是否保持不变。
